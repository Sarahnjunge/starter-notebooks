Prioritizing Content Pages for Search Performance Review

A machine learning ranking experiment using observed search-performance signals
Sarah Njunge · FlyRank ML Internship Capstone · 2026

Abstract

This study asks which content pages should be reviewed first when a content team has limited review capacity. Using the FlyRank internship warehouse, I aggregated eight historical search-performance features over January–March 2026 and defined an attention outcome as an April impression decline of more than 20% relative to March. A Logistic Regression model was evaluated against a historical-impressions baseline using the same client-grouped held-out test set. The model achieved 86.0% Precision@50 compared with 76.0% for the baseline, identifying 43 attention pages in the top 50 compared with 38 for the baseline. The result supports using observed search-performance signals as decision support for human review, rather than treating the model as a causal diagnosis or a guarantee of future performance.

1. Introduction

Problem statement

Content teams may have thousands of pages but limited capacity to review them manually. The practical question is therefore not simply whether a page's search performance changes, but: which pages should be reviewed first?

This project frames the problem as a prioritization task. Instead of attempting to predict the future performance of every page, the model produces a ranked review queue using historical search-performance signals.

Decision supported: prioritize a limited content-review queue using observed historical search-performance signals.

The output is intended for human decision support. A high model score indicates that a page resembles pages that met the defined attention criterion in the evaluation data. It does not establish why performance changed or what action will necessarily improve it.

The analysis uses the FlyRank internship-warehouse release. The warehouse contains daily content-performance records covering approximately January 2025 through June 2026.

Feature window

Historical features were calculated using observations from 1 January 2026 through 31 March 2026.

Pages were required to have at least 60 days with observed Google Search Console data during this period. This produced 70,432 pages before matching with the outcome period.

Outcome window

The evaluation outcome used 1 April 2026 through 30 April 2026.

A page was labelled as needing attention when its April impressions were more than 20% below its March impressions. Pages were also required to have at least 100 March impressions to reduce noise from very small denominators.

3. Methodology

Features

Eight historical search-performance features were calculated from the January–March window:

  • GSC observed days
  • 90-day impressions
  • 90-day clicks
  • 90-day click-through rate
  • 90-day average search position
  • 90-day position volatility
  • Average daily impressions
  • Average daily clicks

Target definition

The target variable was:

needs_attention = April impressions < 80% of March impressions

This is a directional performance label. It does not mean that the page is objectively poor or that its content caused the change.

Baseline

The baseline ranks pages using historical 90-day impressions. The top 50 pages from this ranking form the baseline review queue.

Machine learning model

The model is a Logistic Regression pipeline with median imputation and feature standardization. The model produces a probability score for each page, which is then used to rank the review queue.

Validation design

A GroupShuffleSplit was used with client_hash_id as the grouping variable. This keeps pages from the same client together when creating the training and held-out test sets.

The final test set contained 970 pages. Both the historical-impressions baseline and the ML model were evaluated on this same held-out set.

Leakage check

Features were calculated only from January–March data. April outcome measurements were used only for evaluation and label construction. April outcome variables were not included among the model features.

Leakage audit: feature period and outcome period were separated, and the April outcome was excluded from the model inputs.

Ranking overlap

Only 2 of the top 50 pages appeared in both the ML and baseline rankings. This means the two approaches selected substantially different review queues.

Among the pages selected exclusively by each method, 41 of 48 ML-only pages met the attention criterion, compared with 36 of 48 baseline-only pages.

Secondary metric

The Logistic Regression model achieved 0.581 balanced accuracy on the held-out test set.

Precision@50 remains the primary metric because the intended use case is prioritizing a limited review queue rather than classifying every page equally.

5. Limitations & Honest Framing

The outcome is directional

The attention label is based on an observed change in impressions. A decline in impressions does not establish why the decline happened.

The model does not establish causality

Historical associations between features and the attention score should not be interpreted as causal relationships. The analysis does not establish that changing one of these features would improve search performance.

One evaluation period

The experiment uses January–March 2026 features and an April 2026 outcome. Results may differ across other time periods, clients, industries, or search environments.

Client-held-out, not future deployment validation

The validation split separates clients between training and testing. However, this remains a single held-out experiment rather than a true forward-time production evaluation.

Uneven search-data availability

Google Search Console data is not available for every page and every day. The analysis therefore represents pages with sufficient observed history rather than every page in the warehouse.

Thresholds are modeling choices

The 20% decline threshold and minimum 100 March impressions were chosen for this experiment. Different thresholds could produce different labels and model performance.

Not a complete content recommendation system

The model prioritizes pages for human review. It does not automatically determine which content changes should be made or measure whether an intervention improves performance.

6. Ranked Recommendations

The model produces a ranked review queue using predicted probabilities from the Logistic Regression model. The ranking is intended to determine where limited human review capacity can be allocated first.

High priority — Top 50

Pages in the top 50 are considered first for human review.

Medium priority — Ranks 51–100

Pages ranked 51–100 form the next review group when additional capacity is available.

Lower priority — Below 100

Pages below rank 100 remain eligible for review when business context or new evidence suggests attention is appropriate.

Human review playbook

  1. Check the recent impressions and clicks trend against the historical period.
  2. Examine click-through rate and average search position.
  3. Investigate position volatility when rankings appear unstable.
  4. Inspect the page for outdated information, content gaps, relevance, and technical issues.
  5. Record the evidence considered, review decision, and action taken.

These priority groups are operational queue categories. They are not definitive judgments about content quality or guaranteed predictions of future performance.
